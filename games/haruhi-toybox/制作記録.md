## 0. 出発点

すでに動くHTMLプロトタイプが手元にありました。

- 表紙（箱）＋ミニゲーム3本（くまさんキャッチ／アザラシたたき／アライグマのふきふき）
- 共通の効果音・BGM・音量設定（localStorageに保存）
- HTML / CSS / JavaScript のみ。サーバー不要・**完全オフライン**で動く設計

「Webの作法（HTMLとCSSを分ける、画像はファイル参照、共通部品は1か所）」を守って作ってあったため、
**APK化と非常に相性がよい状態**でした。これが後の判断を楽にしました。

## 1. 最初の分岐：包むか、作り直すか

APK化の入口で、2つの道がありました。

| | A案：今のHTMLをWebViewで包む | B案：プロトタイプとして作り直す（ネイティブ化） |
|---|---|---|
| 手間 | 小さい | 大きい |
| 既存の資産 | そのまま活きる | ほぼ捨てる |
| 完成までの速さ | 速い | 遅い |

**選んだのはA案。** 理由は3つ：

1. **中身はもう完成している。** 動くコードを捨てて作り直すのは、得るものより失うものが大きい。
2. **包むと“待っていた機能”が解禁される。** 「BGMを開いた瞬間から鳴らす」設定は、WebViewに包んで初めて指定できる
   （ブラウザは自動再生を禁止している）。つまり *包む＝完成度が上がる*。
3. **早く届けたい。** 対象は3歳児。子どもの「今」は短い。速く手元に届くA案を優先しました。

> B案（作り直し）は将来の選択肢として保留。土台がHTMLなので、後からでも積み増せます。

## 2. 包む前の検品

包む前に、「本当にオフラインで完結しているか」を機械的に確認しました。

- **外部リンクの全文検索**：`http(s)://` / Google Fonts / CDN への参照は **0件**。ネットに一切依存していないことを確認。
- **画面の向きの確認**：各ゲームの背景画像の縦横を調べ、**すべて横長（landscape）で統一**されていることを確認 → アプリは横向き固定で包めばよいと確定。

> 教訓：「たぶんオフラインだろう」で済ませず、検索で裏を取る。1つでもCDNのフォントを読んでいたら、
> 電波の無い子ども用タブレットで表示が崩れていました。

## 3. つまずきと工夫

実際に手を動かす中で出てきた、小さな判断たち。

- **日本語フォルダ名のリスク**：箱のフォルダ名が「はるひのおもちゃ箱」（日本語）。
  Androidのアプリ内パスで日本語が悪さする恐れがあったため、**包むとき限定でフォルダ名を `box`（英語）に変更**。
  ただし各ゲームの「もどる」ボタンが箱を日本語名で直接指していたので、**コピー側のリンクだけ `box` 向きに書き換え**。
  （元データ（Googleドライブ側）は一切触らず、コピーした作業用だけを直す＝元を壊さない）
- **重い原本を持ち込まない**：制作用の元画像（`original/`）や作業ツールは同梱せず、**実際に動く分だけ**を選別してコピー。
  結果、アプリ内アセットは約13MB、最終APKは圧縮されて **5.58MB** に収まりました。
- **作業はローカルディスク（C:）で**：ふだんの保管はGoogleドライブ（クラウド同期）ですが、
  同期フォルダ上でビルドすると壊れることが過去にあったため、**ビルドはC:で行い、完成したAPKだけクラウドに戻す**段取りに。

## 4. 設計判断：WebViewにどう包んだか

アプリ本体は「HTMLを表示するだけ」のシンプルなものですが、**1つ1つの設定に意図**があります。

```java
WebSettings s = web.getSettings();
s.setJavaScriptEnabled(true);
s.setDomStorageEnabled(true);                  // localStorage（音量設定の保存）を効かせる
s.setMediaPlaybackRequiresUserGesture(false);  // ★BGMを開いた瞬間から鳴らす（包んだ最大の目的）
s.setAllowFileAccess(true);                    // アプリ内の画像・音を読めるように
```

### はるひ（3歳）のための判断

子どもが触ることを前提に、「事故を起こさない」設定を足しました。

- **インターネット権限を付けない**：アプリは通信機能を一切持たない。広告も外部接続もなし＝安心。完全オフライン。
- **画面を常時オン**（`FLAG_KEEP_SCREEN_ON`）：遊んでいる途中で画面が暗くならない。
- **全画面・横向き固定**：ステータスバーやナビゲーションバーを隠し、向きを固定。誤操作でホームに戻りにくく。
- **長押しメニューを無効化**：文字選択やコピーのメニューが出ないように（子どもが触ると邪魔になるため）。
- **Androidの戻るボタンを賢く**：「ゲーム→箱」へ戻れるよう制御。箱でもう一度押すと終了。

```java
// 戻るボタン：ゲーム中ならまず箱へ戻る。箱まで戻っていたら終了。
@Override public void onBackPressed() {
    if (web != null && web.canGoBack()) web.goBack();
    else super.onBackPressed();
}
```

> 設計の軸：**「3歳児が一人で触っても困らない」**。機能を足すより、余計なものを消す方向で整えました。

## 7. 実機テストで発覚した不具合 → v1.1（`_shared` が消えた事件）

v1.0を実機（はるひのタブレット・Android 7.0）に入れたところ、**一部だけが「ごっそり」抜け落ちる**現象が出ました。

- BGMが鳴らない
- 設定ボタンのアイコンが出ない
- もどるボタンのアイコンが出ない
- クリア時の「できたー！」画像が出ない

各ゲーム固有の絵（くま・あざらし・どうぶつ）は正常に出ています。**消えたものの共通点は、すべて `_shared`（共通の画像・BGM・効果音・設定）に置いた素材**でした。

### 切り分けのために：PC内にAndroid 7.0環境を建てた

実機を都度借りずに再現・確認できるよう、**PCの中にAndroid 7.0のエミュレータ（仮想タブレット）**を用意しました。
（このPCはホスト画面のスクリーンショットが壊れていますが、**エミュレータの中身は `adb` 経由で撮れる** ＝ ネロ（AI）が画面を直接見て確認できる、というのが大きな収穫でした。）

### 根本原因：ビルド道具（aapt）の“隠れた仕様”

調べると、原因はコピーミスでも書き間違いでもなく、**道具のクセ**でした。

> **Androidのビルド（aapt）は、既定で「`_` で始まるフォルダ＝作業用」とみなし、APKから黙って除外する。**

`_shared` はC:のアセットに**正しくコピーできていた**のに、APKに固められる瞬間に「これは作業用フォルダだろう」と判断され、**0件＝丸ごと捨てられていた**のです。コピー作業は正しく、犯人は道具の既定動作でした。

### 修正：`build.gradle` をたった1行

`_shared` を「捨てない」よう、除外ルールから `<dir>_*`（_始まりフォルダ）だけを外しました。

```gradle
android {
    androidResources {
        // 既定の除外パターンから「_始まりフォルダ」を外す＝_shared を同梱する
        // （.git や thumbs.db などのゴミは引き続き除外）
        ignoreAssetsPattern '!.svn:!.git:!.ds_store:!*.scc:.*:!CVS:!thumbs.db:!picasa.ini:!*~'
    }
}
```

**HTMLもファイル名も一切変えていません。** パッケージングの設定だけで解決しました。再ビルドすると `_shared` の18ファイルがちゃんとAPKに入り、サイズは **5.6MB → 14MB** になりました。

### 確認

エミュレータでBGMの再生（音声フォーカスの取得・ミキサー稼働）と、設定・もどるアイコンの表示を確認。「できたー！」画像は**ジョーがクリアまで遊んで実証**（絵も音も出て、タイトルに戻るところまで）。**4つの不具合すべて解消。**

→ `はるひのおもちゃ箱_v1.1.apk`（versionName 1.1・14MB）完成。v1.0（不具合あり）も記録として残置しています。

> 教訓：**「コピーしたのに無い」ときは、自分のミスを疑う前に“道具が途中で何を捨てているか”を疑う。**
> アプリが完成して初めて、ビルド道具の既定動作が牙をむくことがありました。実機（または実機相当のエミュ）で通しで触らないと気づけない種類のバグです。

## 9. 制作の“住まい”を整える — フォルダ規約（v1.2に向けて）

v1.1まで、各ゲームは `games/` 直下に平置きで、共通素材は `_shared/` に置いていました。動くものはできましたが、**新しいゲームやプロジェクトを増やすほど散らかる**形でした。

そこで、Web制作で身につけた規律——**「`src/`（製品そのもの）と、原本・道具・実験を、フォルダの境界ではっきり分ける」**——をこのアプリにも適用しました。Webでもアプリでも分け方は同じ。作法は2つ覚えるのでなく、1つを深めます。

```
games/
└ haruhi-toybox/
   ├ src/                   ← 本番（APKに包む＝gitに上げる）
   │   ├ index.html style.css images/   ← 箱（ホーム）
   │   ├ shared/            ← 共通の音・画像・settings.js
   │   └ kuma-catch/ azarashi-tataki/ araiguma-fukifuki/
   ├ originals/             ← 原本（gitにもAPKにも入れない）
   ├ tools/                 ← 調整ツール・バックアップ
   └ docs/                  ← 各ゲームの仕様書
```

**判断の理由：**
- `src/` の中だけが本番。原本・道具・成果物(`*.apk`)は外＝追わない。Webの「`src`だけ公開」と同じ発想。
- 共通素材は「本番で必ず使う材料」なので、`_shared` の `_` を外して **`src/shared/`** に。`_` は本来「裏方の部品」を表す印で、本番材料には付けないのが筋。
- おかげで、v1.1で足した **`build.gradle` のおまじない（7章）は不要に**なります。`src/` だけ包めば原本は自然と外れるので、道具のクセと戦わず構造で解決できます。
- フォルダ名は英語（`haruhi-toybox`）に。Androidのパスで日本語を避けるため（v1.0で `box` に改名した手間も、最初から英語なら不要）。

> この整理は**ソースの置き場所だけ**の変更で、ゲームの中身（HTML/CSS/JS）は無改変。次の v1.2 をビルドするとき、この新しい `src/` から包み直します。

## 付録：最終的なアプリの構成

```
HaruhiToybox/                         ← Androidアプリのプロジェクト（ローカルC:で作業）
 ├─ app/src/main/
 │   ├─ AndroidManifest.xml           ← 権限・画面向き・起動設定（インターネット権限なし）
 │   ├─ java/.../MainActivity.java    ← WebViewでHTMLを表示するだけの本体
 │   ├─ res/                          ← アイコン・テーマ
 │   └─ assets/                       ← H:の haruhi-toybox/src/ をそのまま同梱（＝製品だけ）
 │        ├─ index.html  style.css  images/   ← 箱（ホーム）
 │        ├─ shared/   ← 共通の音・画像・settings.js
 │        └─ kuma-catch/ ほか2ゲーム
 ├─ app/build.gradle                  ← v1.2〜は ignoreAssetsPattern のおまじない撤去（src/だけ包むので不要）
 └─ （Gradle設定一式）
```
